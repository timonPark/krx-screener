# krx-screener 프론트엔드 명세

> 상태: 화면 코드(`frontend/`)는 예시 데이터로 동작한다. 백엔드 웹 서버는 아직 없다.
> 작성일: 2026-11-06 · 짝 문서: `docs/backend-design.md` (백엔드 설계, 11장이 이 화면의 요약)
> 이 문서는 `frontend/` 의 실제 동작을 기준으로 쓰고, 설계 문서와 다른 곳은 12장에 모았다.

## 1. 범위

- 한 화면에서 세션을 고르고, 목록을 조회하고, 구간을 정해 처리하고, 정리(순위)를 실행한다.
- 화면은 **백엔드 주소(API)만 부른다.** 분석·점수·순위 계산은 모두 백엔드가 한다. 화면은 표시와 입력만 한다.
- 빌드 없는 정적 파일이다 (HTML, CSS, JS 모듈). 사용자는 한 명이고 로그인은 없다.

## 2. 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대 (구역과 입력 요소) |
| `styles.css` | 색·글꼴 토큰(`:root`)과 컴포넌트 스타일 |
| `app.js` | 화면 상태, 그리기, 버튼 동작, 처리 중 주기적 갱신 |
| `api.js` | 백엔드 호출. 경로는 이 파일에만 있다 |
| `mock.js` | 백엔드 없이 보는 예시 API (`?mock=1`) |
| `config.js` | API 주소, 갱신 간격, 보고서 링크 주소 등 |

실행은 정적 서버로 연다 (`file://` 은 ES 모듈이 막힌다). 백엔드가 이 폴더를 같이 서빙하면 `apiBase: ''` 그대로 쓰고 CORS가 필요 없다. 다른 포트에서 따로 띄우면 백엔드가 CORS를 허용해야 한다.

## 3. 화면 구성

위에서 아래로 다음 순서다.

| # | 구역 | 내용 |
|---|---|---|
| 1 | 상단 바 | 제목 "KRX Screener", 예시 데이터 태그(mock일 때만), 갱신 표시(점 + 문구) |
| 2 | 세션 | 세션 선택, 세션 정보(기준일·뽑은 시각·종목 수·필터 문구), 새 목록 뽑기 |
| 3 | 진행 요약 | 처리 진행 `n / 전체`, 상태별 개수, 진행 막대 |
| 4 | 안내 띠 | 순위 낡음(경고), 오류(에러). 해당할 때만 보인다 |
| 5 | 조회 표 | 처리 여부 칩, 정렬, 12개 열, 표 아래 개수 문구 |
| 6 | 처리 | 오프셋·개수 입력, 대상 범위, 예상 시간, "처리 시작" |
| 7 | 정리 | "정리 실행" 버튼과 상태 문구 |

## 4. 구역별 동작

### 4.1 상단 바
- 갱신 점: 처리 중이면 깜박이는 점(`live`), 아니면 회색 점. 사용자가 모션 줄이기를 켰으면 깜박이지 않는다.
- 문구: 처리 중이면 `처리 중 · 10초마다 갱신 · 마지막 HH:MM:SS`, 아니면 `마지막 갱신 HH:MM:SS` (한국 시각).

### 4.2 세션
- **세션 선택**: 최근 순 목록. 첫 항목에 `(최근)`을 붙인다. 표시는 `{기준일}-{id 앞 8자리}` (예: `2026-11-05-3f2a9c1b`). 세션이 없으면 "세션 없음 — 새 목록을 뽑으세요".
- **세션 정보**: 기준일, 뽑은 시각(`MM-DD HH:MM`, 한국 시각), 종목 수, 필터 문구. 필터 문구는 현재 화면에 고정된 글자다(20일 평균 거래대금 10억↑ · 종가 > 20일선 · 종가 > 60일선).
- **새 목록 뽑기**: 기준일을 날짜로 입력한다. 기본값은 직전 영업일(평일 기준, 공휴일은 모른다). 누르면 새 세션을 만들고 그 세션을 선택한다. 필터·정렬을 처음 상태로 돌리고 오프셋을 0으로 되돌린다. 버튼은 "뽑는 중…"으로 바뀌고 끝나면 돌아온다.

### 4.3 진행 요약
- `처리 진행 n / 전체`: n은 **완료 + 실패**. 상태별 개수는 완료 · 처리 중 · 실패 · 대기.
- 막대는 전체 대비 비율로 완료, 실패, 처리 중을 차례로 채운다.

### 4.4 안내 띠
- **순위 낡음**: 세션 응답의 `rank_stale`이 true면 표시. "정리 이후 다시 분석된 종목이 있습니다. 최신 순위를 보려면 정리를 다시 실행하세요."
- **오류**: 백엔드가 준 한국어 메시지(`detail`)를 그대로 띄운다. 서버에 연결하지 못하면 "서버에 연결하지 못했습니다. 백엔드가 켜져 있는지 확인하세요."

### 4.5 조회 표
- **처리 여부 칩**: 전체 · 대기 · 처리 중 · 완료 · 실패, 각각 개수를 같이 보인다. 하나만 선택된다.
- **정렬**: 순번(기본) · 점수 높은 순 · 순위.
  - 점수 정렬은 점수가 없는 종목을 맨 뒤로 보내고, 같으면 순번 순서다.
  - 순위 정렬은 순위가 없는 종목을 맨 뒤로 보내고, 같으면 순번 순서다.
- **열 (12개)**

| 열 | 표시 |
|---|---|
| 순번 | 거래대금 큰 순서, 1부터 |
| 종목 | 종목명, 투자주의·외국기업 표시, 아래에 `종목코드 · 시장` |
| 업종 · 기업 설명 | 업종명, 아래에 기업 설명(길면 줄임, 마우스를 올리면 전체) |
| 수급 | 점 + 상태 글자. 마우스를 올리면 외국인·기관 5거래일 순매수(주) |
| 종가 | 천 단위 구분 |
| 평균 거래대금 | 억 단위 반올림 (예: `2,017억`) |
| RSI | 소수 첫째 자리 |
| 처리 | 상태 배지, 아래에 보조 문구 |
| 최종 등급 | 완료된 종목만 |
| 평가점수 | 완료되고 점수가 있는 종목만 |
| 순위 | 정리 후 숫자, 전에는 "—" |
| 보고서 | 보고서 번호 (7장) |

- 처리 중인 줄은 배경으로 구분한다.
- **처리 보조 문구**: 완료는 분석한 시각, 실패는 `사유 · 다시 처리하면 재시도`, 처리 중은 `분석 중`.
- 표 아래: `전체 N개 중 M개 표시`, "점수는 분석이 끝난 종목부터, 순위는 정리 실행 후 채워집니다". 조건에 맞는 종목이 없으면 "조건에 맞는 종목이 없습니다."

### 4.6 처리
- **입력**: 오프셋(0 이상 정수, 기본 0), 개수(1 이상 정수, 기본 10).
- **대상 범위**: `오프셋+1 ~ 끝 번호`로 표시. 값이 올바르지 않거나 오프셋이 종목 수 이상이면 "—".
- **예상 시간**: 범위 안에서 **끝나지 않은 종목 수 × 종목당 분(설정, 기본 5)**. 60분 이상이면 "N시간 M분".
- **힌트와 버튼**

| 상황 | 버튼 | 힌트 |
|---|---|---|
| 처리 중 | 막힘, "처리 중…" | "이 세션은 이미 처리 중입니다 (지금 N번 종목명). 서버에 취소 기능이 없어 중간에 멈출 수 없습니다." |
| 입력이 올바르지 않음 | 막힘 | "오프셋은 0 이상, 개수는 1 이상의 정수로 입력하세요." |
| 오프셋 ≥ 종목 수 | 막힘 | "오프셋이 종목 수(N)보다 크거나 같습니다." |
| 범위의 종목이 모두 완료 | 막힘 | "이 구간의 종목은 모두 끝났습니다. 다른 구간을 고르세요." |
| 그 외 | 활성 | "이 구간에서 N개를 보냅니다 (끝난 M개는 건너뜀). 누르면 바로 시작 응답을 받고 처리는 뒤에서 진행됩니다." |

- 처리 중에는 오프셋·개수 입력도 막힌다.
- 누르면 `POST …/process`. 응답을 받으면 조회를 다시 부르고, 처리 중이면 주기적 갱신을 시작한다. 이미 처리 중이면 서버가 409를 주고 화면은 그 메시지를 띄운다.

### 4.7 정리
- **남은 개수** = 대기 + 처리 중. **실패는 남은 개수에 넣지 않는다** (비교에서 제외되므로).
- 버튼 이름: 한 번도 안 했으면 "정리 실행", 했으면 "정리 다시 실행".
- 남은 게 있으면 막고 "남은 N개가 끝나야 실행할 수 있습니다".
- 남은 게 없으면 활성. 문구는 최신 순위면 `최신 순위입니다 (시각)`, 실패가 있으면 `실패 N개는 비교에서 제외됩니다`, 그 외 "실행할 수 있습니다".
- 정리를 마치면 정렬을 **순위**로 바꾼다.

## 5. 갱신 규칙

- 처음 열 때: 세션 목록을 불러와 최근 세션을 고르고 그 세션을 조회한다.
- **조회는 처리 중일 때만 주기적으로 다시 부른다.** 간격은 설정값(기본 10초). 처리 중이 아니면 멈춘다.
- 세션을 바꾸거나 버튼을 누른 뒤에는 한 번 다시 조회한다.
- 버튼 동작 중에는 버튼을 막고(`busy`), 끝나면 풀린다. 오류가 나면 안내 띠에 띄운다.

## 6. 표시 규칙

| 항목 | 규칙 |
|---|---|
| 시각 | 서버 시각은 UTC 문자열로 받아 **한국 시각**으로 `MM-DD HH:MM` 표시 |
| 세션 표시 | `{기준일}-{id에서 하이픈을 뺀 앞 8자리}` |
| 거래대금 | 서버는 원 단위로 주고 화면이 억으로 바꾼다 |
| 점수 | 부호(+/−) 붙이고 소수 둘째 자리 (예: `+0.30`, `−0.60`). 0은 부호 없음 |
| 점수 막대 | ±2를 최대 30px로 환산해 양수는 한쪽 색, 음수는 다른 색. 아래에 `에이전트 n/m` |
| 값 없음 | "—" (수급 합계는 읽지 못한 경우 툴팁에 "읽지 못함, 수급 0 아님") |
| 색 | **국내 관례**: 매수·양수는 빨강, 매도·음수는 파랑 |
| 등급 색 | 매수 · 비중 확대 · 보유 · 비중 축소 · 매도에 각각 별도 색 (모르는 값은 보유 색) |
| 수급 | 점의 **색과 모양**을 함께 바꾼다 (양호·부분·약함·미확인). 미확인은 점선 계열 |
| 처리 배지 | 대기(회색), 처리 중(보라), 완료(초록), 실패(주황) + 점 |
| 표시만 하는 종목 | 이름 옆에 "투자주의", "외국기업" 작은 표시 |

글꼴은 IBM Plex Sans KR(본문)과 IBM Plex Mono(숫자)이고 Google Fonts에서 불러온다.

## 7. 보고서 번호

- 보고서 칸은 **TradingAgents-KR의 보고서 번호(`report_id`)**를 보여준다. 예: `028050_20261106_172435`.
- `config.reportUrlTemplate`에 `{report_id}`가 들어간 주소를 정하면 번호가 TradingAgents-KR 보고서 화면으로 가는 링크가 된다. 정하지 않으면(null) 글자로만 보인다.
- 실행 번호(`run_id`)는 화면에 표시하지 않는다.
- **현재 코드는 `run_id`를 보여주고 `{run_id}`로 링크를 만든다. TradingAgents-KR 보고서 화면은 `report_id`를 쓰므로 링크가 열리지 않는다. 이 명세대로 고쳐야 한다** (12장).

## 8. API 계약

경로는 화면이 제안한 형태다. 바꾸면 `api.js`만 고친다. 키는 영어이고, 사용자에게 보이는 값(`flow_status`, `decision_label`, 오류 `detail`)은 한국어다.

| 기능 | 요청 | 응답 |
|---|---|---|
| 1 목록 뽑기 | `POST /api/sessions` `{"as_of": "2026-11-05"}` | `Session` |
| 세션 목록 | `GET /api/sessions` | `Session[]` (최근 순) |
| 3 조회 | `GET /api/sessions/{id}` (`id`에 `latest` 가능) | `SessionDetail` |
| 2 나눠서 처리 | `POST /api/sessions/{id}/process` `{"offset": 0, "count": 10}` | `202 {"started": true, "queued": 7}` · 처리 중이면 `409 {"detail": "이미 처리 중입니다."}` |
| 4 정리 | `POST /api/sessions/{id}/organize` | `200 {"ranked": 115, "unscored": 0}` · 남았으면 `409 {"detail": "…", "remaining": 3}` · 처리 중이면 `409 {"detail": "이미 처리 중입니다.", "remaining": N}` |

오류는 모두 `{"detail": "한국어 메시지"}`이고 화면이 그대로 띄운다.

```jsonc
// Session
{ "id": "3f2a9c1b7d4e…", "as_of": "2026-11-05", "created_at": "2026-11-06T00:12:00Z", "total": 116 }

// SessionDetail
{
  "session": Session,
  "processing": false,     // 이 세션을 처리 중인지(잠금). true면 화면이 주기적으로 다시 부른다
  "ranked_at": null,       // 정리 실행 시각, 안 했으면 null
  "rank_stale": false,     // 정리 이후 재분석된 종목이 있으면 true
  "counts": { "pending": 112, "running": 0, "done": 3, "failed": 1 },
  "items": [Item, …]       // 세션 전체, 순번 순
}

// Item
{
  "seq": 1, "code": "028050", "name": "삼성E&A", "market": "KOSPI",
  "sector_code": "", "sector_name": "건설", "description": "…",
  "is_caution": false, "is_foreign": false,
  "close": 64800, "avg_trading_value": 201712536740, "rsi": 67.2,
  "flow_status": "부분",                       // 양호 | 부분 | 약함 | 미확인
  "foreign_net_5d": -624606, "institution_net_5d": 645940,   // 못 읽으면 null
  "state": "done",                             // pending | running | done | failed
  "analyzed_at": "2026-11-06T01:20:00Z", "error_message": "",
  "report_id": "028050_20261106_172435",       // 7장: 보고서 번호 (현재 코드는 run_id)
  "decision_label": "보유", "score": 0.3, "agents_rated": 10, "agents_total": 10,
  "rank": null                                  // 정리 전 null
}
```

## 9. 설정 (`config.js`)

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `apiBase` | `''` | API 주소. 백엔드와 같은 주소에서 서빙하면 빈 문자열 |
| `pollMs` | 10000 | 처리 중일 때 조회를 다시 부르는 간격 |
| `reportUrlTemplate` | null | 보고서 링크 주소. `{report_id}`가 번호로 바뀐다 |
| `minutesPerItem` | 5 | 종목당 예상 분석 시간(분) |
| `mock` | 주소에 `?mock=1` | 예시 데이터로 동작 |
| `mockMsPerItem`, `mockPollMs` | 3000, 1000 | 예시 모드에서 종목 하나를 처리하는 시간, 조회 간격 |

## 10. 예시 모드 (`?mock=1`)

- 백엔드 없이 14개 종목을 보여준다. 시세·수급과 앞 3종목의 등급은 실제로 돌린 값이고, 나머지 등급·점수·업종 설명은 화면 확인용 예시다.
- 처리를 누르면 종목마다 3초씩 처리하는 것처럼 보이고, 처리 중에 다시 누르면 409를, 남은 게 있는 상태에서 정리를 누르면 409를 낸다. 정리는 점수 높은 순, 같으면 순번 순으로 순위를 매긴다.

## 11. 접근성과 입력

- 구역마다 이름이 있고(`aria-label`), 안내 띠는 상태 알림(`status`)·오류 알림(`alert`) 역할이다. 칩은 선택 여부를 `aria-pressed`로 알린다.
- 수급 점은 색만으로 구분하지 않고 모양도 바꾼다.
- 키보드로 이동할 때 포커스 표시가 있다.
- 표는 가로로 넘치면 구역 안에서 스크롤한다. 입력 요소는 높이 44px이다.

## 12. 설계 문서와 다른 점 · 고쳐야 할 것

1. **보고서 번호**: 현재 코드는 `run_id`, 이 명세는 `report_id` (7장). 백엔드는 `report_id`를 내려주고, 화면은 `app.js`의 보고서 칸과 `config.js`의 주소 자리표시자를 `report_id`로 바꾼다.
2. **필터 문구가 고정 글자**다. 조건(5번)이 바뀌어도 화면은 모른다. 백엔드가 세션마다 쓴 조건을 내려주도록 바꿀 수 있고, 지금은 고정 문구로 둔다.
3. **직전 영업일 계산**은 공휴일을 모른다. 기본값일 뿐이고 사용자가 날짜를 고칠 수 있다.
4. 예시 모드에서 없는 세션 id로 처리를 부르면 오류가 난다 (예시 모드에서만).
5. 화면이 설명하는 "종목당 약 5분"은 설정값이다. 실제 소요 시간은 측정값(약 5분 13초)과 다를 수 있다.

## 13. 화면이 하지 않는 것

- 처리 취소 (서버에 취소 기능이 없다)
- 상대 등급, 동점 묶기 (설계에서 제외)
- 점수·순위 계산 (백엔드가 한다)
