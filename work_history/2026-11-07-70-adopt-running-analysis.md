# [fix] 시간 초과 뒤 재처리가 서버의 도는 분석을 이어서 기다린다 (#70)

- 브랜치: feat/70-skip-duplicate-run (main 위)
- 작업일: 2026-11-07
- 요청: #70 ("#70 부터 진행하세요"). 설계안을 보여 드렸고 사용자가 **이어서 기다린다**, **목록을 못 읽으면 예전처럼 새로 보낸다** 로 정했다.

## 수행한 변경

- `AnalysisClient.find_running(ticker, trade_date)`: 서버의 `GET /api/runs?limit=20` 에서 같은 종목·기준일의 `pending`/`running` 분석을 찾아 `run_id` 를 준다 (여럿이면 가장 먼저 시작한 것). 목록을 읽지 못하면(없는 주소, 오류 응답, 연결 실패, 모양 이상) `None` + 경고 로그 — 이 확인 때문에 분석이 막히지 않는다.
- `run_one`: 보내기 전에 `find_running` 을 부른다. 있으면 새로 보내지 않고 그 `run_id` 로 이어서 기다린다 (INFO 로그). 웹(`processing.py`)과 명령줄(`cli.py`)이 같은 `run_one` 을 써서 **한 곳의 수정으로 둘 다** 적용된다.
- `externals.AnalysisServer` 프로토콜에 `find_running` 추가.
- 테스트의 가짜: `FakeAnalysisServer` 가 실제 서버처럼 끝나지 않은 분석을 기억하고(같은 종목을 또 보내도 거절하지 않고 새로 시작) `running_since()` 로 "앞서 시작해서 아직 도는 분석" 을 만든다. 다른 가짜(`test_analysis.FakeClient`, `test_analyze_command` 의 FakeClient)에도 `find_running` 추가.
- 문서: `docs/backend-design.md` 13장(재시도 한계 서술을 새 동작으로), README 상단 상태 줄, `analysis.py` 의 모듈 설명.

## 설계 결정

- 새로 보내기 전 확인은 `run_one` 한 곳에 둔다 (웹·명령줄 공통). 응답 필드·API 는 바뀌지 않는다.
- 이어서 기다릴 때도 `timeout_seconds` 는 이어서 기다리기 시작한 시점부터 센다. 이어서 기다려도 시간 초과가 나면 다시 실패로 표시되고, 다시 처리해도 또 이어서 기다릴 뿐 쿼터를 더 쓰지 않는다.
- 서버의 `run_id` 는 메모리에서만 쓴다 (저장·노출하지 않는다는 원칙 유지).

## 이슈에 없던 결정

1. `RUN_LIST_LIMIT = 20` (서버 기본값). 도는 분석은 늘 최근이라 충분하다고 가정했다.
2. 이어서 기다린 종목의 `elapsed_seconds` 는 이어서 기다린 시간만 잰다 (분석의 총 시간이 아님).

## 실제 서버 확인 (완료 조건 4번, 사용자가 쿼터 1번분 확인)

임시 DB·임시 설정(후보 3개, 시간 초과 60초)으로 삼성바이오로직스(207940) 1개를 실제 TradingAgents-KR 로 확인했다.

| 시각(KST) | 일 |
|---|---|
| 10:46:11 | 첫 분석 `76aa95` 시작 (서버 목록에 207940 분석 1개) |
| +61초 | 60초 안에 끝나지 않아 항목이 **실패**, 서버의 `76aa95` 는 계속 `running` |

## 알려진 한계

- 실제 서버로 확인한 것은 종목 1개의 한 경우다 (목록에서 찾는 `pending`/`running` 분석이 `running` 일 때). `pending` 인 분석, 서버 재시작으로 목록이 빈 경우, 목록을 읽지 못하는 서버 버전은 가짜 서버·단위 테스트로만 확인했다.
- 서버가 재시작돼 run 목록이 비면 확인할 수 없다 (이 경우 새로 보내서 쿼터가 두 번 든다).
- 응답에 `effort`·`analysts` 가 없어서 설정이 다른 분석(예: 사람이 서버 화면에서 돌린 것)도 이어받는다. 에이전트별 등급 개수(`agents_rated`)로 차이가 드러날 뿐 막지는 않는다.
- 분석 목록 응답에 보고서 본문이 들어 있어 무겁다 (run 5개 415KB, 20개면 약 1.7MB). 종목을 시작할 때마다 한 번 부른다. 로컬이라 문제 없다고 보지만 측정하지는 않았다.
