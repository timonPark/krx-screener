# [#22] 평가점수 계산·저장

- 이슈: https://github.com/timonPark/krx-screener/issues/22 (에픽 #5, 스펙 #1)

## 수행한 변경

- `src/krx_screener/scoring.py` 신규: `score_ratings(ratings)` → `Score(score, rated, total)`.
  - 등급 → 점수: 매수 +2, 비중 확대 +1, 보유 0, 비중 축소 −1, 매도 −2 (`RATING_POINTS`).
  - 점수 = 등급을 낸 에이전트 전부의 평균. 비중은 모두 같고 강세·약세도 포함한다.
  - 읽지 못한 에이전트는 평균에서 뺀다 (빈 칸을 0 으로 치지 않는다). 하나도 못 읽었으면 점수는 `None`.
  - 등급을 낸 수(`rated`)와 전체 수(`total` = `AGENT_TOTAL` = 10)를 같이 돌려준다.
- `processing.py`: #21 이 읽은 에이전트별 등급으로 점수를 계산해 `mark_done(score, agents_rated, agents_total)` 에 넘긴다.
  (이전에는 `score=None, agents_rated=0, agents_total=0` 자리표시였다.)
- 테스트: `test_scoring.py` 10개, `test_process_api.py` +8 (자리표시를 단언하던 기존 2개는 새 동작으로 고쳤다).

## 설계 결정 (이슈 #22 범위 안에서 내가 정한 것)

- **`agents_total` 은 항상 10** (로그를 읽지 못해도). 그래서 "읽지 못함"은 `0/10`, 점수 `None` 으로 보이고, 아직 처리하지 않은 종목(`0/0`)과 구별된다.
- **평균은 정수 합을 정수 개수로 한 번만 나눈다.** 같은 평균이면 부동소수 값이 정확히 같아서(3/6 == 1/2) 정리(#24)의 "점수가 같으면 순번" 동점 규칙이 오차로 깨지지 않는다.
- **5단계에 없는 값은 읽지 못한 것으로 본다** (판독기가 이미 걸러내지만 방어로). 점수 계산은 최종 등급(`decision`)을 쓰지 않는다 — 에이전트의 등급만으로 계산한다.
- 점수를 반올림하지 않고 그대로 저장한다 (화면이 표시할 때 자릿수를 정한다).
- 재분석 성공 시 점수가 새 값으로 바뀌고, 재분석이 실패하면 `mark_failed` 가 점수를 건드리지 않는다 (#19 동작 그대로, 기존 테스트로 확인).

## 알려진 한계

- **점수가 좁은 구간에 모인다.** 실제 로그에서는 −0.9~+0.4 뿐이었다. 에이전트 대부분이 보유·비중 축소를 내서 평균이 0 근처로 몰린다.
  종목 간 순위를 가르는 용도로는 쓸 수 있지만 "점수 1.0 이상" 같은 절대 기준을 두기에는 값이 작다 (정리 이후 화면에서 확인할 일).
- **읽은 수가 적을수록 점수가 불안정하다.** 3/10 로 계산한 점수와 10/10 점수는 같은 눈금이지만 신뢰도가 다르다. 그래서 수를 같이 저장한다 (화면 표시는 #27~).
- 실제 서버로 분석을 돌려 끝까지 확인하지는 않았다 (분석 1회 약 5분·쿼터). 계산은 순수 함수와 실제 로그 13개로, 저장 흐름은 가짜 서버로 확인했다.
