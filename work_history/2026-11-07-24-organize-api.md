## 수행한 변경

- `routes_sessions.py`: `POST /api/sessions/{id}/organize` (`latest` 가능).
  - `200 {"ranked": N, "unscored": M}`.
  - 대기·처리 중인 종목이 하나라도 있으면 `409 {"detail": "남은 N개가 끝나야 정리할 수 있습니다.", "remaining": N}` — 아무것도 바꾸지 않는다.
  - 처리 중인 세션이면 `409 {"detail": "이미 처리 중입니다.", "remaining": N}`.
- `repository.py`: `SessionRepository.organize(session_id) -> Ranking(ranked, unscored)` — 한 트랜잭션에서 이전 순위를 지우고,
  끝난(`done`) 종목 중 점수가 있는 것에 `row_number() OVER (ORDER BY score DESC, seq ASC)` 로 순위를 매기고, 정리 시각(`sessions.ranked_at`)을 적는다.
- 테스트 `test_organize_api.py` 25개 (처리부터 정리까지 이어지는 흐름 1개 포함). 문서: `docs/frontend-spec.md` API 표, `docs/backend-design.md` 정리 절.

## 설계 결정 (이슈 #24 범위 안에서 내가 정한 것)

- **점수가 없는 완료 종목은 순위에서 뺀다** (`unscored` 로 개수를 알린다). 에이전트 등급을 하나도 못 읽은 종목인데 #22 에서 "점수를 지어내지 않는다"고 정했고,
  0점으로 순위에 넣으면 보유와 같은 줄에 서고, 맨 뒤에 두면 가장 나쁜 종목으로 읽힌다. 이슈 본문에는 없는 결정이라 응답에 `unscored` 를 더했다 (화면이 쓰지 않아도 해가 없다).
- **처리 잠금(#18)을 정리도 쥔다.** 정리하는 동안 같은 세션의 처리가 시작되면 점수가 바뀌며 순위가 어긋난다. 잠금을 못 쥐면 "이미 처리 중입니다."(409).
  처리 연결이 아직 열려 있지만 남은 종목이 0인 짧은 순간도 여기에 걸린다. 잠금은 연결을 닫을 때 풀린다 (정리 뒤에도 남지 않음을 테스트로 확인).
- **정리할 때마다 처음부터 다시 매긴다.** 이전 순위를 모두 지운다 — 정리 뒤에 실패로 바뀐 종목이 옛 순위를 갖고 있으면 안 된다. 같은 상태에서 다시 정리하면 같은 순위가 나온다.
- **실패 종목은 옛 점수가 남아 있어도 순위에 넣지 않는다** (#19: 재분석이 실패해도 기존 등급·점수는 남는다). 상태가 `failed` 이면 비교에서 빠진다.
- 순위는 1부터 빠짐없이 이어진다 (동점 묶기 없음). 동점은 순번이 앞선 종목이 위이고, 점수는 #22 가 정수 합을 한 번만 나눠서 같은 평균이면 정확히 같은 수다
  (읽은 에이전트 수가 달라도 동점으로 잡힌다 — 테스트로 확인).
- 종목이 없는 세션은 `{"ranked": 0}` 으로 성공하고 정리 시각을 적는다. 모두 실패한 세션도 막지 않는다.

## 검증 결과

- `pytest`: 테스트 DB 연결 시 **541 passed** (이전 516), DB 없이 345 passed·196 skipped. `ruff` 통과.
- 변이 검사 9종 모두 테스트가 잡았다(확인 후 원복): 동점을 뒤 순번이 위로, 점수 낮은 순, 실패 종목 포함, 점수 없는 종목을 0점으로, 이전 순위를 지우지 않음,
  실패를 남은 개수에 포함, 처리 잠금 무시, 남아 있어도 정리, 정리 시각 미기록.
- 완료 조건 대조(웹 API 경계, 진짜 Postgres): 남은 종목이 있으면 순위가 매겨지지 않고 남은 개수가 응답에 있다 ✓ / 실패 종목은 순위에서 빠지고 정리를 막지 않는다 ✓ /
  동점일 때 순번 순서가 지켜진다 ✓.
- 처리(`POST …/process`) → 정리(`POST …/organize`) → 조회(`GET …`)를 가짜 서버로 끝까지 이어서 순위와 `ranked_at` 이 조회에 보이는 것을 확인했다.

## 알려진 한계

- 처리하다 프로세스가 죽어 `running` 으로 남은 종목은 "남은 개수"에 들어가 정리를 막는다 (이슈 본문 그대로: 대기·처리 중). 같은 구간을 다시 처리하면 풀린다.
- 순위 "낡음" 표시(`rank_stale`)는 아직 항상 `false` 다 — #25 가 한다. 정리 후 재분석하면 순위가 낡아도 지금은 표시되지 않는다.
- `ranked_at` 은 정리를 시작한 트랜잭션의 시각(`now()`)이다.
