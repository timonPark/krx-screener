- 브랜치: test/58-browser-tests (main 위, #57 머지 뒤)
- 작업일: 2026-11-07
- 요청: #58 "브라우저 자동 테스트를 저장소에 넣을지 검토하고 정한다" ("#58 진행하세요")

## 결정: 넣는다

이유: 화면 규칙(오류 알림이 사라지는 때, 정리 막힘, 진행 표시)을 `app.js` 가 실제로 연결했는지는 그동안 문자열 확인뿐이었다. #28 에서 헤드리스 Chrome 으로 찾은 결함("동작 오류 알림이 20ms 만 보임")과
#56·#57 에서 화면을 바꿀 때마다 일회성 스크립트로 확인한 것이 모두 저장소 밖에 있었다. 이번에 넣은 테스트는 그 확인을 반복 가능하게 만들었고, 처음 돌린 뒤 실제 백엔드 버그를 하나 찾았다 (아래).

## 수행한 변경

- `tests/browser_harness.py`: 실제 백엔드 + 테스트 PostgreSQL + 실제 `frontend/` 에 시세·수급·분석 서버만 가짜로 끼운 서버를 스레드로 띄운다.
  테스트 전용 `POST /__ctl` 로 실행 중에 가짜를 조작한다 (`errors`, `polls`, `health_error`, `db_down`, `build_gate`). 제어 **파일**(이전 일회성 방식)이 아니라 같은 프로세스의 주소를 쓴다.
  `config.js` 는 갱신 간격만 짧게 바꿔 내려준다 (갱신 코드는 그대로 돈다).
- `tests/browser/cdp.mjs`, `tests/browser/scenarios.mjs`: 외부 패키지 없는 CDP 클라이언트(Node 22 의 WebSocket·fetch)와 시나리오. 화면에서 본 사실을 JSON 으로 내고 판정은 pytest 가 한다.
- `tests/test_browser_screen.py`: 시나리오 5개 — 새 목록(진행 `3 / 8`·중복 409·조건 문구), 처리와 정리(갱신·정리 막힘·실패 종목·낡음·다시 정리), 오류 알림(409·503·422·DB 꺼짐의 남고 사라지는 규칙), 만들지 못한 목록, 예시 모드. 콘솔 오류가 있으면 실패.
  Node 22 이상·Chrome·테스트 DB 중 하나라도 없으면 건너뛴다. Chrome 경로는 macOS 기본 또는 `KRX_SCREENER_CHROME`.
- **백엔드 수정(아래 "찾은 버그")**: `routes_sessions.py` 의 세션 조회, 회귀 테스트 2개(`tests/test_session_lock.py`).
- `docs/api-testing.md` 에 브라우저 테스트 실행법과 제어 방법.

## 찾은 버그

- **세션 조회가 종목을 먼저 읽고 처리 잠금을 나중에 확인했다.** 그 사이에 처리가 끝나면 `running` 종목이 있는데 `processing=false` 로 답해서, 화면이 갱신을 멈추고 마지막 종목이 영원히 "처리 중" 으로 남았다 (새로고침하면 풀림).
  브라우저 시나리오가 실행마다 약 1/10 로 멈춰서 찾았다 (화면 `3 / 8, 처리 중 1, 갱신 멈춤` / 서버 `processing=false, running=0`).
- 수정: 잠금을 종목을 읽기 **전과 후** 모두 보고 하나라도 쥐고 있으면 `processing=true`. 읽는 도중에 시작한 처리도 같은 식으로 잡힌다.
- 이 수정은 #58 요청 밖이다. 테스트가 안정적으로 돌려면 필요했고 사용자에게 보이는 결함이라 같은 PR 에 넣었다.

## 이슈에 없던 결정

1. 브라우저 테스트는 **기본 `pytest` 에 포함**한다 (환경이 있으면 돈다, 약 30초). 이슈는 "있으면 통과" 를 완료 조건으로 했다. 느리면 마커로 분리할 수 있다.
2. 제어 파일 대신 테스트 전용 `/__ctl` 주소를 쓴다 (제품 코드에는 없고 테스트 서버에만 붙인다).
3. 테스트 서버가 `config.js` 의 갱신 간격을 바꿔 내려준다. 바꾸는 문자열이 `config.js` 에 없으면 테스트가 바로 실패한다.

## 검증 결과

- `ruff check src tests` 통과, `pytest` 712 passed (약 51초, 이 중 브라우저 테스트 약 27초).
- **변이 검사**(원본 복원 확인): `notice.js` 의 동작 오류 유지 규칙 제거 → 2개 실패, `app.js` 의 낡음 띠 표시 제거 → 1개 실패. 백엔드 수정은 되돌렸을 때 새 회귀 테스트가 실패하는 것을 확인했다 (수정 전 빨강 → 수정 후 초록).
- 불안정성: 수정 전 처리 시나리오 반복에서 3번째에 실패했고, 수정 후 같은 시나리오를 25번 반복해 모두 통과했다. 전체 파일은 수정 뒤 6번 연속 통과. **경쟁이 완전히 사라졌다는 증명은 아니다.**

## 알려진 한계

- **작업 중 사고**: 변이 검사를 중단하셨을 때 `frontend/app.js` 가 변이된 채로 남았고(첫 보고에서 "실행되지 않았다" 고 잘못 말했다), 백업본으로 복원한 뒤 작업 트리가 의도한 변경뿐임을 확인했다. 이후 변이 검사는 복원까지 확인하며 다시 했다.
- 변이 검사는 일부 규칙(오류 유지, 낡음 띠)에만 했다. 정리 막힘·진행 숫자·실패 카드는 변이로 확인하지 않았다.
- 브라우저는 Chrome 한 종류, macOS 경로 기준이다. 다른 OS·브라우저는 확인하지 못했다 (`KRX_SCREENER_CHROME` 로 다른 Chrome 을 가리킬 수는 있다).
- CI 가 없어 자동으로 돌아가지는 않는다. 로컬에서 환경이 있을 때만 돈다.
- 실제 TradingAgents-KR 로 웹 처리를 끝까지 보는 것은 #59 (쿼터 사용, 실행 전에 묻는다).
