## 수행한 변경

- **운영 코드 변경 없음.** 이 이슈의 동작(실패 표시·사유 저장·재시도·시간 초과 사유·기존 등급 보존)은 #17 의 구간 처리,
  `analysis.run_one`, `repository.mark_failed` 에 이미 들어 있었다. 이 이슈에서 한 일은 그 동작을 **웹 API 경계에서 검증하는
  테스트로 고정**한 것이다.
- `tests/test_process_failures.py` 신규 11개:
  - 시간 초과: 실패로 표시되고 사유에 "기다리기를 멈췄습니다 … 서버에서는 계속 실행 중일 수 있음" 이 남는다. 나머지 종목은 계속 간다.
  - 사유: 처리 도중 서버 오류(분석을 찾지 못함)는 한국어 사유로 남고, 조회의 `error_message`·`counts.failed` 에 보인다.
    서버가 받지 않는 영숫자 코드(`0126Z0`)는 보내지 않고 "숫자 6자리" 사유로 실패 처리하며 나머지는 계속 간다.
  - 재시도: 시간 초과로 실패한 종목은 다음 호출에서 성공으로 바뀌고 사유가 지워진다. 같은 구간을 다시 부르면 실패한 종목만 다시 보낸다.
  - 기존 등급 보존: 등급이 있던 종목의 재분석이 실패하거나 시간 초과여도 등급·점수·에이전트 수·보고서 번호·에이전트별 등급이
    그대로 남고, 재분석 중에도 이전 등급이 보인다. 재분석이 성공하면 새 등급으로 바뀐다.

## 설계 결정

- 코드를 고치지 않은 이유: 완료 조건 세 개가 #17 구현으로 이미 만족됐다. 같은 동작을 다시 구현하면 중복이다.
- 시간 초과 테스트는 설정의 `timeout_seconds` 를 0, 확인 간격을 0.001 로 바꿔서 실제로 기다리지 않는다.
- "등급이 있는데 failed" 상태는 저장소로 `mark_done` 뒤 `mark_failed` 를 불러 만든다. 지금 API 로는 끝난(`done`) 종목을 다시
  분석할 수 없어서, 이 상태는 이전 재분석이 실패했거나(앞으로 재분석이 생길 때) 옛 데이터에서만 생긴다.

## 검증 결과

- `pytest`: 테스트 DB 연결 시 **396 passed**, DB 없이 **245 passed, 151 skipped**. `ruff` 통과.
- 변이 검사(테스트가 실제로 잡는지): (1) `mark_failed` 가 등급을 지우게 바꾸면 보존 테스트 3개 실패, (2) 시간 초과 사유에서 "서버에서는
  계속 실행 중일 수 있음" 을 빼면 시간 초과 테스트 실패, (3) 실패한 종목을 재시도 대상에서 빼면 재시도 테스트 6개 실패. 확인 후 원복.
- 완료 조건 대조: 실패 종목의 상태 `failed` + 사유 ✓ / 재시도하면 성공으로 바뀜 ✓ / 재분석이 실패해도 기존 등급 유지 ✓.

## 알려진 한계

- **시간 초과 뒤 바로 재시도하면 쿼터를 한 번 더 쓴다.** 서버에는 취소 API 가 없어 앞서 보낸 분석이 계속 돌고 있을 수 있다.
  서버가 같은 종목·기준일의 동시 실행을 어떻게 다루는지는 확인하지 않았다 (쿼터를 쓰는 일이라 실제로 돌려 보지 않았다).
- **재분석이 성공해도 이전의 에이전트별 등급 행은 이 이슈에서 지우지 않는다.** 새 에이전트별 등급을 읽어 통째로 바꿔 넣는 일은 #21 이다
  (`save_agent_ratings` 가 통째로 교체한다).
- 영숫자 종목코드는 `failed` 로 표시되어 구간을 부를 때마다 "다시 시도" 되지만 서버로는 가지 않는다 (쿼터 소모 없음).
