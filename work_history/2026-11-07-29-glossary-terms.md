# [#29] GLOSSARY에 새 용어 추가 (세션·평가점수·순위·정리)

- 이슈: https://github.com/timonPark/krx-screener/issues/29 (에픽 #8, 스펙 #1)
- 브랜치: docs/29-glossary-terms (main 위)
- 작업일: 2026-11-07

## 수행한 변경

- `GLOSSARY.md` 에 새 용어 4개를 정의했다: **세션**, **평가점수**, **순위**, **정리**. 뜻만 적고 구현 세부(테이블·API 주소·잠금 등)는 넣지 않았다.
- 기존 용어와 충돌하는 두 곳을 고쳤다:
  - **`등급` 의 `_Avoid_` 에 "점수"가 있었다.** 새 용어 `평가점수`와 정면으로 부딪힌다. `_Avoid_` 를 "스코어, 점수 (점수는 평가점수를 가리킨다)"로 바꾸고,
    `등급` 정의에 "숫자로 바꿔 평균한 평가점수와는 다른 값이다"를 더했다. "후보는 등급이 아니다"라는 기존 구분은 그대로다.
  - **`분석 대기열`** 에 세션과의 관계("명령줄에서는 기준일마다 하나의 세션이 분석 대기열 역할을 한다")를 한 문장으로 더했다.

## 용어 정의에서 내가 정한 것

- **세션**: "기준일에 한 번 뽑은 후보 목록 + 처리 상태·등급·평가점수·순위를 묶은 단위". 같은 기준일로 여러 번 뽑아도 서로 영향이 없다는 점을 넣었다 (UUID·저장 방식 같은 구현은 뺐다).
  `_Avoid_`: 실행, 배치, 작업 — "실행"은 `run` 명령(1단계 실행)과 헷갈린다.
- **평가점수**: 환산표(`매수` +2 … `매도` −2)는 **정의의 일부**라서 넣었다. "읽지 못한 에이전트는 평균에서 빼고, 하나도 못 읽으면 비어 있다(0이 아니다)"도 같은 이유로 넣었다
  (설계 문서의 "점수를 지어내지 않는다"). `_Avoid_`: "점수(단독으로 쓰지 않는다)".
- **순위**: 1부터 빠짐없이, 동점은 목록에서 앞선 후보가 위, 동점 묶기 없음. "투자 판단이 아니라 같은 세션 안에서 후보를 견주는 순서"라고 적어 후보≠등급 구분을 이어 간다. `_Avoid_`: 등급, 상대 등급, 랭킹.
- **정리**: 모든 후보가 처리된 뒤에만, 실패는 비교에서 빠짐, 정리 뒤 재분석하면 순위가 "낡음". `_Avoid_`: 마감, 확정, 랭킹 계산.

## 검증 결과

- `[[링크]]` 가 가리키는 용어가 모두 정의되어 있다 (정의 안 된 링크 없음, 용어 10개).
- `_Avoid_` 충돌 점검: 새 용어가 다른 용어의 금지어와 겹치는 곳은 위에서 고친 `등급`의 "점수" 하나뿐이었다. 점검에서 더 걸린 2건은 오탐이다 —
  `수급 상태`의 "수급 등급"(기존부터 '등급은 최종 결정 라벨'을 지키려는 금지어), `순위`의 "등급"(순위를 등급이라 부르지 않기, 기존 `수급 상태` 항목과 같은 패턴).
- 문서만 바꿨다 (코드·테스트 변경 없음). `pytest`·`ruff` 는 이 PR 로 영향이 없다.

## 알려진 한계

- 다른 문서(`docs/frontend-spec.md`, 화면 문구)는 "점수"를 단독으로 쓴 곳이 있다 (예: "점수 높은 순", 표 머리글). 사용자에게 보이는 문구라 이번에 고치지 않았다 — 화면 머리글은 "평가점수" 이다.
- `보고서 번호`, `에이전트별 등급`, `보관` 같은 용어는 이슈 범위(4개)가 아니라 넣지 않았다.
