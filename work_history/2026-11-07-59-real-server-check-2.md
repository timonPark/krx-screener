- 작업일: 2026-11-07
- 요청: #59 의 남은 항목 ("#59 진행하세요"). 사용자가 쿼터 범위를 **전체(분석 4번, 약 25분)** 로 확인해 주었다.

## 방법

- 개발 DB 와 분리한 임시 DB(`krx_screener_real59b`, 확인 뒤 삭제)와 임시 설정 2개로 실제 서버(`http://127.0.0.1:8000`)에 보냈다.
  - 후보를 3개로 줄이려고 `filters.min_avg_trading_value_krw` 를 1천억으로 올렸다 (삼성E&A 2017억·셀트리온 1230억·삼성바이오로직스 1148억). 순위 정리는 **모든 종목이 처리된 뒤에만** 되어서, 후보 116개로는 실제 서버로 정리를 확인할 수 없었다.
  - 1단계: `analysis.timeout_seconds` 를 60초로 줄인 서버로 셀트리온을 보내 일부러 시간 초과를 만든다.
  - 2단계: 서버를 기본 시간 초과로 다시 띄우고 **같은 종목을 바로 다시 보낸다** (앞선 분석은 서버에서 아직 도는 중).
  - 3단계: 나머지 2종목을 한 번에 처리하고 화면을 15초 간격으로 기록한다 (헤드리스 Chrome, CDP). 끝난 뒤 정리를 실행한다.
- 서버의 `GET /api/runs` 와 DB 를 10초 간격으로 기록해서 대조했다.

- **쿼터를 한 번 더 쓴다**: 같은 종목 전체 분석이 2번 돌았다. 서버가 쿼터 사용량을 기록하지 않아 값은 못 쟀다.
- **먼저 끝난 분석의 결과는 버려진다**: 이 도구의 항목은 실패였다가 재시도의 결과(보고서 `…102048`, 점수 +0.40, 에이전트 10/10)로 채워졌다. 첫 분석의 보고서는 서버에만 남았다.
- 두 분석이 동시에 도는 동안 느려지는 정도는 작았다 (단독 316초 → 동시 359~363초).
- 같은 종목·기준일의 **두 분석이 서로 다른 점수**를 냈다: 처음(09:53, #66) +0.20 (비중 확대 3·비중 축소 1), 이번 재시도 +0.40 (매수 2·비중 확대 1·비중 축소 1). 최종 등급은 둘 다 보유다.

### 여러 종목 연속 처리와 정리 (완료 조건의 남은 부분)

| 종목 | 걸린 시간 | 등급 | 점수 | 에이전트 | 보고서 |
|---|---|---|---|---|---|
| 1 삼성E&A | 301초 | 비중 축소 | −0.30 | 10/10 | 028050_20261107_102613 |
| 2 셀트리온 | 361초(재시도) | 보유 | +0.40 | 10/10 | 068270_20261107_102048 |
| 3 삼성바이오로직스 | 341초 | 보유 | +0.30 | 10/10 | 207940_20261107_103153 |

- 연속 처리는 한 종목씩 차례로 돌았다 (서버의 `running` 이 한 번에 하나). 셋 모두 새 상태 로그를 읽어 등급 10/10 이 저장됐다.
- 정리: `ranked 3, unscored 0` → 1위 셀트리온(+0.4), 2위 삼성바이오로직스(+0.3), 3위 삼성E&A(−0.3). 새로 연 화면에서 `최신 순위입니다` 와 순위 칸이 보였고 콘솔 오류가 없었다.

### 처리 중 화면 갱신 (실제 5~6분 분석)

- 처리 중 화면은 `처리 중 · 10초마다 갱신`, 시작 버튼 막힘, "지금 N번 종목명" 안내를 유지했고, 종목이 끝날 때마다 줄이 갱신됐다 (1번 완료 → 10:26 반영, 3번 완료 10:31:53 → 10:31:58 에 반영되고 갱신이 멈춤). 기록은 15초 간격이라 반영 지연은 "10초 이내" 정도로만 말할 수 있다.
- **발견**: 쉬는 중인 화면은 자동으로 갱신하지 않는다. 처리를 API 로 시작했을 때 이미 열려 있던 화면은 처리가 시작된 것을 몰랐고, 새로고침해야 갱신이 시작됐다 (다른 탭이나 명령줄이 시작한 처리도 같다).
- 한 종목이 약 5~6분이라 처리 중 줄은 그동안 "분석 중" 으로 유지된다 (서버가 중간 진행률을 주지 않는다).

## 틀린 가정 / 설계에 영향이 있는 것

1. **"서버가 같은 종목 재전송을 거절하거나 중복 처리하지 않을 것" 이라는 가정은 틀렸다.** 지금 도구는 시간 초과를 "실패" 로 보고 재처리를 허용해서, 서버에서 아직 도는 분석이 있어도 새 분석을 보낸다 (쿼터 2배).
2. 점수는 같은 입력으로도 달라질 수 있다 (+0.2 / +0.4). 종목끼리의 순위가 가까울 때는 한 번의 점수 차이로 뒤바뀔 수 있다.

## 확인하지 못한 것

- 분석 쿼터 사용량 (서버가 기록하지 않는다).
- 서버가 오류로 끝나는 분석을 실제 서버로 내 본 것 (이번 실행은 모두 성공했다).
- 서버의 로그 폴더가 다른 컴퓨터에 있는 경우.
- 첫 분석(`e703a9`)의 점수 — 상태 로그가 재시도에 덮어써져 읽을 수 없다.
- 5분 동안의 화면은 15초 간격으로만 기록했다 (세밀한 반영 지연은 모른다).
